# 包装标签与每日归档

## 使用

1. 登录后打开饮食页，拍照或上传JPG/PNG/WebP（15MB以内）。点击“打开相机”直接取景，授权后点击“拍照并识别”，无需选择文件；优先后置摄像头。需要 HTTPS 或本机 localhost / 127.0.0.1，手机访问局域网 HTTP 地址不能直接取景。拒绝授权、无摄像头时可上传图片。关闭、拍照完成、切页、退到后台或退出账号时释放相机，取消后迟到的授权结果也会立即释放。
2. 照片在本机使用Tesseract.js 6.0.1及中英文模型识别。结果和照片同时显示；识别含糊的字段留空。可修改识别文本重新提取或直接手填。NRV%不是成分含量，范围值、双列含量不会自动当成精确数值。
3. 核对基准：每100g填100；每份30g填30；每100ml填100并提供密度。能量保留kJ/kcal原值，kJ÷4.184换算kcal，不强制4/4/9。填写克数后即时预览，可补充钠、纤维、维生素等g/mg/μg字段。
4. 勾选核对后记录，同时可保存到食物库。实际餐食营养仍受标签舍入、生产批次和称重误差影响；“精确”指按确认后的标签比例计算，不能保证照片识别零误差。

照片不上传、不保存到服务端；确认的营养数据、识别文本、来源和克数保存到账号业务库，导出JSON时一起保留。后端校验标签和每100g换算值一致性。首次使用加载本服务自带的识别资源，不调用DeepSeek或外部OCR服务。助手读取业务记录时仍遵循已有发送至DeepSeek的说明。

## 每日归档

- archives以本地YYYY-MM-DD为键，保存meals和trainings。旧账号字段兼容，加载后迁移尚存的previous记录。
- 饮食跨日搬入对应日期，今天保持独立，重复刷新不重复归档。跨日未结束且有训练组的训练保留后自动结束，标注“跨日归档”。
- 每次结束训练立即保留完整训练快照；previous只作为最近同类索引。每个训练日可有多次同类型训练，不再覆盖历史。
- 今天训练默认展开，往日训练/饮食默认折叠，展开才构建详细表格。历史包含来源和标签营养快照，不因食物库更新而改变。
- 原版本已清空的旧饮食、已覆盖且没有备份的训练无法凭空恢复；新归档开始于升级时仍存在的数据。
- 无前台页面运行时，在下一次登录/刷新加载时进行归档；页面打开期间每30秒和恢复可见时检查日期。

## 构建与验收

运行npm ci与npm run build，构建脚本复制锁定的OCR脚本、WASM、语言包和许可证到frontend/public/vendor/ocr，manifest.json含SHA-256。交付ZIP已经包含构建产物，Docker/普通Python部署无需运行时从CDN下载资源。修改后重启后端并刷新网页。

自动测试覆盖kJ换算、每份、毫升密度、NRV与缺失值、重复归档、同类多次训练、旧数据迁移、跨日未结束训练、账号隔离、标签持久化和后端一致性校验。浏览器使用独立nutrition_test合成数据验证图片识别（含待核对字段）、35g=70kcal的确认保存、刷新后的日期折叠与展开。照片质量差时使用核对表单补全；未在真实手机摄像头上进行硬件拍照测试。
